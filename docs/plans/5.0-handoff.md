Written 2026-11-19. Read `docs/plans/5.0.md` first; this file says what changed in the last session and what to do next.

## State of the plan

`docs/plans/5.0.md` is a plan only. No 5.0 code exists yet. Baseline source is v4.1.0 (`dd53cd6`); 4.2 ships first from `4.x` and is merged forward (section 2).

## Decisions made this session (maintainer)

- G2 closed: car support ships in 5.0. The plugin stores nothing. Android Auto lives in the plugin. CarPlay is a native bridge plus an example; the entitlement, Info.plist scenes and template UI stay in the host app. watchOS and WearOS are not claimed.
- G13 closed: CarPlay = bridge plus example (option A). Not a plugin-shipped scene delegate and templates.
- G14 decided: a public native API on a Flutter-free core, same process only, shipped inside the existing plugin packages. A standalone core artifact (Maven and Swift package) for separate-process targets (watchOS, Wear OS, Automotive OS) is a later extraction.
- Public native types are the plugin's own (`RadioPlayerSnapshot`, `RadioSourceInfo`, `RestoredPlayer`). The Pigeon `*Message` classes stay internal.
- The host persists its own data. The plugin offers a restore hook on each platform (Kotlin `RadioPlayerRestoreProvider`, Swift protocol) that the host registers at startup.
